### <a name="_qmphm5d6rvi3"></a>**Решение**
Аннотация

Открытие депозита:
1. Процесс открытия депозита начинается с просмотра клиентом на сайте условий по депозитам
2. После выбора депозита клиент оформляет заявку на сайте
3. Заявка поступает в интернет-банк и через интеграцию в СУБД АБС (Статус заявки - "new")
4. Сотрудник отдела депозитов расчитывает индивидуальные условия (Статус заявки - "value")

5. Система кол-центра запрашивает заявки со статусом "ставка" по API интернет-банка (оператор кол-центра озвучивает условия депозита клиенту).
6. Если клиент согласен на открытие депозита на индивидуальных условиях, то оператор колл-центра нажимает кнопку в системе колл-центра и статус заявки меняется на "approved", далее выполняется открытие депозита в АБС
7. Если клиент не согласен на индивидуальные условия, но хотел бы выбрать из списка доступных, то статус "approved" + в комментарии указанные условия
8. Если клиент отказывается от заявки, то статус "rejected".
9. В системе колл-центра реализован механизм очереди заявок, если заявки не могут быть обработаны операторами колл-центра, то они становятся доступны внешнему колл-центру (необходимо реализовать интеграцию с передачей минимума персональных данных (ФИО + телефон + ставка) в виде файла при помощи email, ответ также ожидаем в виде email с определенного адреса )
10. В случае изменения статуса заявки клиенту отправляется смс оповещение через шлюз

Обновление данных по доступным депозитам и ставкам:
1. Сотрудник отдела депозитов ведёт справочные данные в АБС (данные фиксируются в БД АБС).
2. Интернет-банк с периодичностью раз в сутки запрашивает справочные данные из БД и заносит их в кэш
3. Сайт и система колл-центра запрашивают по API интернет-банка данные по депозитам и ставкам.

Если есть возможность (работы выполняет подрядчик), то доработки интернет-банка выполнить в новом модуле (не затрагивая существующий монолит), в качестве кэша использовать Redis. Доработки системы колл-центра и АБС выполняются специалистами банка.

В целевом решении - на горизонте года индивидуальные ставки необходимо рассчитывать автоматически (исключить этот функционал из АБС), также колл-центр необходимо подключать только для уведомления/в маркетинговых целях (также уйдёт из процесса согласования ставки с клиентом).
Нужно больше информации для проработки процесса и задач.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Опишите здесь наиболее важные альтернативные решения.

В случае если нет возможности доработать монолитное решение интернет-банка можно реализовать требуемую функциональность в виде микросервиса на Java стеке (так как специалисты есть в банке).

**Недостатки, ограничения, риски**

Недостатки - необходимость привлечения подрядчика (доп функциональность в монолитном приложении интернет-банка), повышается нагрузка на интернет-банк.

Недостаток обмена данных в виде файла - ненадежность обмена (в случаем если email шлюз недоступен нет возможности проверить статус обработки). Необходимо учитывать размер файла отправляемого по почте (при необходимости файл нужно дробить и архивировать).

Риски - невозможность доработок АБС, интернет-банка, системы колл-центра в требуемые сроки (необходима оценка со стороны команд разработки).
